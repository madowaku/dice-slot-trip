# DICE SLOT TRIP ラスベガスカジノ リニューアル指示書

対象: Claude Code（Opus 5.5）
リポジトリ: `madowaku/dice-slot-trip`（Godot 4.7 / GDScript、縦持ち）
推奨配置: `docs/goals/dice-slot-trip-las-vegas-casino-renewal/goal.md`

---

## 1. 背景と目的

ラスベガスのカジノは「なんとなくすごろくだけだと寂しいから」追加された場所で、目的がはっきりしていない。その結果、次の状態になっている。

- 通常ステージでカジノチップを貯める → カジノで遊ぶ、で流れが終わっていて、遊ぶ理由が弱い
- 6施設あるが、初見プレイヤーには何のゲームか伝わらない
- ゲームの面白さの種類が偏っている

**今回の目的：カジノを「旅のための道具を手に入れる場所」にする。**

新しいコアループ：

```
通常ステージでチップを貯める
  → カジノで遊んでチップを増やす
  → 景品カウンターで「旅ダイス」を手に入れる
  → 旅ダイスを持って通常ステージへ。旅の遊び方が変わる
  → また周回してチップを貯める
```

景品の方針：**強くなる道具ではなく、旅の遊び方が変わる道具。** 通常ダイスより常に有利なものは作らない。何かを得る代わりに何かを失うトレードオフを持たせる。

## 2. 現状診断（2026-08-28時点の main で確認済み）

参考キャプチャ: `artifacts/playtest/las-vegas-casino-expansion/final360/`, `final720/`

### 構成

- 入口: `scenes/app/Main.tscn` → `scripts/app/main_casino_entry.gd` → `scenes/casino/CasinoHub.tscn` / `scripts/app/casino_hub_screen.gd`
- 施設（6）: DICE RACE / DICE TOWER / TREASURE 21 / VAULT BREAK / DICE ROULETTE / DICE POKER
  - 画面: `scripts/app/*_screen.gd`、ロジック: `scripts/game/*_model.gd`
  - `high_low_*` は DICE ROULETTE に置き換え済みの旧ゲーム
- チップ管理: `scripts/game/casino_bank.gd`（`user://dice_slot_trip_casino.json`、`SAVE_VERSION := 2`、`COIN_TO_CHIP_RATE := 2`、`CLEAR_CHIP_BONUS := 5`）
- チップの獲得: `scripts/app/v06_play_screen_casino.gd`、`scripts/app/journey_stage_screen_kyoto_readability.gd`（`_bank_casino_chips_for_completed_lap`）
- 景品: `data/casino/prize_cards.json`（今はレーサー6種、各50チップ。旅への効果なし）
- 旅側のダイス: `KyotoJourney.roll(face: int)` / `AmazonJourney.roll(face: int)` は出目を外から受け取る。旅側のアイテムは `stage_journey_base.gd` の `item_inventory` 系
- 3Dダイス表示: `scripts/game/dice_presentation_3d.gd`（DICE TOWER で使用中）

### UI/UXの問題

1. **ハブ**: 6施設のボタンがすべて「PLAY」で、何のゲームか分からない。背景の絵の密度が高く、文字が埋もれる。PRIZE COUNTER が施設と同じ重さで並び、チップの使い道が伝わらない。
2. **サイコロが主役になっていない**: 各ゲームの画面の6割ほどが空のパネル＋キラキラ＋ルールの文章。DICE POKER ではダイスが「DIE 1 / 1 / OPEN」という文字のボタンになっている。
3. **倍率表でルールを伝えようとしている**: 「LOW ×1.40」「LUCKY7 ×2.35」「FIVE 2.0x・FOUR 1.7x…」。初見ではほぼ読まれない。
4. **画面ごとに作りが揃っていない**: 戻るボタンが「EXIT」「カジノへ戻る」「カジノホールへ戻る」の3通り。ヘッダーの構造も画面ごとに違う。

### ゲームデザインの問題

- TREASURE 21 / DICE TOWER / VAULT BREAK の3つは、どれも「振る → 続けるか降りるか」という同じ種類の判断。
- ROULETTE と RACE は「賭けたら見ているだけ」。
- 数のわりに遊びの幅が狭い。

## 3. 決定事項（オーナー承認済み）

- ゲームは **4つに絞る。**

| 役割 | ゲーム | 方針 |
|---|---|---|
| 入口 | **丁半**（新規） | ルールが一言で済み、1タップで遊べる。初めてカジノに来た人が最初に遊ぶもの |
| 見せ場 | **DICE RACE** | 残す。既存のレーサー資産を活かす |
| 考える | **DICE POKER** | 残す。ダイスを大きく見せる形に作り直す |
| 攻める | TREASURE 21 / DICE TOWER / VAULT BREAK から **1つ** | Phase 3 で比較し、オーナーが選ぶ |

- 外す施設は **コードもテストも削除しない。** ハブから到達できなくするだけにする（後で戻せるように）。
- 景品は **「旅の遊び方が変わる」旅ダイス** を中心にする。既存のレーサー景品は DICE RACE の応援レーサーとして残してよい。

## 4. 共通ルール（全フェーズ）

### 技術的な制約

- Godot 4.7 / GDScript のまま。縦持ち（720×1280 基準、360×800 でも崩れない）。
- ゲームロジックは Control ノードから独立させる。RNG はシードを注入できるようにし、決定論的にテストできる形にする。
- `CasinoBank` のセーブ互換を壊さない。セーブ形式を変える場合は `SAVE_VERSION` を上げ、v2 からの移行処理とそのテストを書く。
- **触らない範囲**: 通常の COIN / LIFE / ステージの仕組み、署名・エクスポート設定、APK、BGM・音源ファイル。
- `journey_stage_screen.gd`（約6000行）と `v06_play_screen.gd`（約4400行）には、Phase 4 の最小限のフック以外で手を入れない。

### UIの原則

- **サイコロが画面の主役。** ダイスは大きく、実物として見せる（可能なら `dice_presentation_3d.gd` を再利用）。
- 全ゲームで同じ画面の型を使う：
  - 上部: ゲーム名 / チップ残高 / 戻るボタン（表記は「カジノへ戻る」に統一）
  - 中央: テーブルとダイス（画面の主役）
  - 下部: 賭け金の選択と、主ボタン **1つ**（今押すべきボタンが常に1つだけ目立つ状態）
- 倍率は「×1.40」ではなく「**勝てば +28**」のように、選んだ賭け金での結果額で見せる。
- ルール説明は、各ゲームの初回だけ **3ステップ以内** の短いガイドにする。2回目以降は「？」ボタンから開く。
- 静かで情報密度の低い画面にする。激しい点滅や情報の詰め込みは避ける。ラスベガスらしさは、色と光のアクセントで出す。

### 検証

- テスト: `& 'C:\Dev\Tools\Godot-4.7-stable\Godot_v4.7-stable_win64_console.exe' --headless --path . --script tests/run_tests.gd` と、関連する `tests/run_casino_*.gd` などが通ること。
- 新しいロジックには、シード固定の単体テストを追加する。
- 画面を変えたフェーズでは、360×800 と 720×1280 のキャプチャを撮り、変更前と並べて `artifacts/playtest/las-vegas-casino-renewal/phaseN/` に保存する（`tests/record_las_vegas_casino_expansion.gd` を参考にする）。
- Godot を実行できない環境の場合は、その旨を報告に明記する。「通ったはず」と書かない。

### Git

- 作業ブランチ: `feat/casino-renewal`（main から作る）
- コミットはフェーズ内でも小さく分ける。
- push はフェーズの承認後に行う。

## 5. フェーズ

### Phase 0: 調査と計画（コードは書かない）

1. 上の現状診断が今のブランチでも正しいか確認する。違う点があれば報告する。
2. 次の点を調べて報告する：
   - 共通画面の型を作るうえで再利用できるもの（Theme、既存のボタン部品、`dice_presentation_3d.gd`）
   - `CasinoBank` に「所持している旅ダイス」と「装備している旅ダイス」を保存する方法と、移行の方針
   - 京都ステージで、出目が決まって `roll(face)` に渡る場所。旅ダイスを差し込める最小のフック
3. Phase 1〜4 の作業計画（触るファイル、追加するテスト、リスク）を書く。

### Phase 1: 共通の型、ハブ、丁半

1. 共通のカジノ画面の型（ヘッダー、テーブル領域、下部アクション、初回ガイド、結果表示）を作る。
2. **ハブを「景品棚」中心に作り直す：**
   - 一番目立つ位置に「ねらっている景品」と「あと何チップ必要か」を出す
   - 施設は4つ。それぞれ一言の説明（例：「丁か半か、当てるだけ」）と、遊び方のイメージがわかる小さな絵を付ける
   - 背景の絵は文字の後ろで暗くするかぼかし、読みやすさを優先する
   - Phase 1 の時点では、まだ移行していない施設は今の画面のまま開いてよい
3. **丁半を新しく作る：**
   - ダイス2個。合計が偶数なら丁、奇数なら半。当たれば賭け金の2倍が戻る
   - 操作は「賭け金を選ぶ → 丁か半をタップ → 振る」。壺を伏せて開く演出があると良い
   - ゾロ目のサイドベットは入れない（入口のゲームを単純に保つため）
4. テストとキャプチャを撮る。**停止して報告する。**

### Phase 2: DICE POKER と DICE RACE を共通の型へ

- DICE POKER: 5個のダイスをテーブルに大きく並べ、タップでキープする（キープ中は浮かせる・枠を付けるなど、見て分かる形）。役表は常に全部出さず、今の手が何の役でいくら勝てるかを出す。
- DICE RACE: 今の演出は活かしたまま、ヘッダー、下部アクション、結果表示を共通の型に揃える。
- ルールの数値（倍率、確率）は変えない。見せ方だけを変える。
- **停止して報告する。**

### Phase 3: 「攻めるゲーム」を1つに絞る

1. TREASURE 21 / DICE TOWER / VAULT BREAK を比較したレポートを書く：
   - 1プレイの長さ、判断の回数、判断の面白さ（どれだけ悩むか）、ルールを一言で言えるか、実装の完成度
   - 各ゲームを、共通の型でどう見せるかの案
   - 推奨と、その理由
2. **停止して、オーナーの選択を待つ。**
3. 選ばれたゲームを共通の型へ移行する。外す2つと DICE ROULETTE はハブから到達不可にする（コードとテストは残す）。
4. **停止して報告する。**

### Phase 4: 旅ダイス（景品）と京都ステージへの組み込み

**データと景品カウンター：**

- `data/casino/` に旅ダイスの定義を追加する。各ダイスは「6つの面の値」と説明文で表現する。
- 初期の旅ダイス（効果は仮。オーナーの確認後に確定）：

| 名前 | 面 | 遊び方がどう変わるか | 失うもの |
|---|---|---|---|
| 刻みダイス | 1,1,2,2,3,3 | 狙ったマスに止まりやすい | 遠くまで進めない |
| 偶数ダイス | 2,2,4,4,6,6 | 偶数マス先の目標を狙える | 奇数マスには止まれない |
| 一か八かダイス | 1,1,1,6,6,6 | 大きく進むか、ほぼ進まないか | 中間の目が出ない |
| 寄り道ダイス | 3,3,3,4,4,4 | 安定して中くらい進む | 大きく進めない、ほぼ同じ目しか出ない |

- 価格は仮で 80〜150 チップ。レーサー景品（50チップ）との関係も含めて、チップの貯まる速さから妥当な値を提案する。
- 景品カウンターで購入する → 所持リストに入る → ステージ開始前に1つ装備できる、という流れにする。
- `CasinoBank` に「所持」と「装備」を保存する（移行処理とテストを含む）。

**京都ステージへの組み込み（ここだけ。他のステージには入れない）：**

- 装備中の旅ダイスは、1ステージにつき **3回まで** 使える。振る前に「通常ダイス／旅ダイス」を切り替えられる。
- 実装は、出目を生成する1か所で、装備中のダイスの面から出目を選ぶだけにする。`roll(face)` 以降の処理は変えない。
- 旅ダイスで振ったときは、ダイスの見た目（色など）で分かるようにする。
- 旅ダイスなしでも、今までどおり最後まで遊べることをテストで確認する。

**停止して報告する。** 他のステージへの展開と、スロット絵柄の景品は次回以降に検討する。
