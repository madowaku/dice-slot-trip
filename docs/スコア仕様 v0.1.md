\# DICE SLOT TRIP スコア仕様 v0.1



\## 0. 目的



通常旅行を、タイムに追われるゲームではなく、



> \*\*旅を続けるほど数字が育ち、次はもっと伸ばしたくなるスコアアタック\*\*



として設計する。



通常旅行ではタイム、PB、LAPを評価に使わない。タイムアタックは専用コース・専用記録へ分離する。



\---



\## 1. 基本方針



\### スコアとコインは別物



\* \*\*スコア\*\*：その周の旅の成果。使っても減らない

\* \*\*コイン\*\*：イベントや補給で消費するゲーム内資源



コインを使ったことでスコアまで減る仕様にはしない。

「賢く使ったのに記録が下がった」という逆風を避ける。



\### スコアは減らさない



v0.1では減点を入れない。



RISKに止まってもスコアを奪わず、HPやコインなどのゲーム内資源で不利益を受ける。スコア表示は、基本的に右肩上がりのメーターとして扱う。



\### 通常旅行では時間を評価しない



\* HUDにタイマーを表示しない

\* クリア時間をスコアへ加算しない

\* 遅く遊んでも不利にならない

\* ポーズや図鑑確認で焦らせない



内部計測をQAや統計用に保存するのはよいが、プレイヤーの通常スコアには影響させない。



\---



\## 2. スコアの5分類



周回結果では、次の5項目に分けて表示する。



```text

旅　　　　マスを進み、道を開いた点

スロット　MIX / PAIR / STRAIGHT / TRIPLE

発見　　　アイテム、イベント、円環、宝物

ボス　　　周回ボスレース

完走　　　ステージ完走と残りHP

```



プレイヤーが「何を改善すれば次の記録が伸びるか」を見つけやすくする。

\# 3. 配点



\## 3.1 旅スコア



| 行動          |  スコア |

| ----------- | ---: |

| 未訪問マスへ1マス進む |  +10 |

| 同じマスを再訪する   |   +0 |

| 分岐でルートを選ぶ   |  +50 |

| バイパスを完走する   | +300 |



\### 未訪問マスのみ加点



円環をぐるぐる回ることで無限に得点できないよう、各ノードの移動点は\*\*1周につき初回訪問だけ\*\*加算する。



6を出して未訪問マスを6個進んだ場合は、



```text

+10

+10

+10

+10

+10

+10

```



と、猫の着地に合わせてスコアが小刻みに増える。



高い出目の気持ちよさは残るが、同じ場所を周回して稼ぐことはできない。



\---



\## 3.2 停止マススコア



| マス           |    スコア | 備考              |

| ------------ | -----: | --------------- |

| NORMAL       |     +0 | 移動点のみ           |

| COIN         |    +50 | コイン獲得とは別に加点     |

| REST         |    +40 | 回復できなくても初回停止で加点 |

| ITEM         |   +120 | アイテム取得時         |

| EVENT        |   +150 | イベント処理完了時       |

| WARP         |   +100 | ワープ成立時          |

| BRANCH       |    +50 | 選択確定時           |

| RISKを受ける     |     +0 | 減点もしない          |

| RISKをアイテムで防ぐ |   +150 | 水筒やゴーグルによる防御成功  |

| BOSS GATE    |   +200 | 周回ボス到達          |

| TREASURE     | +1,000 | 黄金スカラベなど        |



同一マスからスコアを得られるのは、原則として1周に1回だけ。



RISKそのものには得点を付けず、準備によって防いだ場合だけ「うまい旅」としてボーナスを与える。



\---



\## 3.3 3ROLL SLOTスコア



| 役        |  スコア | 既存報酬     |

| -------- | ---: | -------- |

| MIX      |  +50 | コイン+1    |

| PAIR     | +150 | スキルゲージ+1 |

| STRAIGHT | +350 | スキルゲージ+2 |

| TRIPLE   | +800 | スキルゲージ+3 |



3ROLL SLOTは、移動先と役を同時に考えさせる第二の判断軸として維持する。



\### 表示方法



3枠目へ数字が入ったあと、スロット内で非モーダル表示する。



```text

\[4] \[1] \[6]



MIX

+50　コイン+1

```



\* 背景暗転なし

\* 確認ボタンなし

\* 約300〜500ms表示

\* 自動で移動処理へ進む

\* 次のROLL開始時に3枠を空にする



スロット結果のために旅のリズムを止めない。



\---



\## 3.4 探索スコア



| 行動         |         スコア |

| ---------- | ----------: |

| オアシス環から脱出  |        +400 |

| 墓廊の輪から脱出   |        +600 |

| 黄金スカラベ取得   |      +1,000 |

| 初めてのイベント発見 | 通常点に加えて+100 |

| 初めてのアイテム登録 | 通常点に加えて+100 |



円環は正確停止でEXITへ止まる判断が必要なので、本線の通常マスより大きな得点にする。カイロには練習用のオアシス環と、危険で報酬の大きい墓廊の輪がある。



図鑑登録ボーナスは、同じセーブデータで初回のみ。周回ごとには繰り返さない。



\---



\## 3.5 周回ボススコア



眠そうなスフィンクスとの鏡面レースを、各周の締めとして扱う。



| 結果      |      スコア |

| ------- | -------: |

| ボスレース完走 |     +500 |

| 勝利      | 追加+1,000 |

| 敗北      |     追加なし |

| 完全同着勝利  |  通常の勝利扱い |



したがって、



```text

敗北：+500

勝利：+1,500

```



となる。



敗北してもスコアは増える。再挑戦を要求せず、その周の結果として記録するというボス設計に合わせる。



ボスへ勝った人だけ次周が有利になるアイテム報酬は、v0.1では付けない。



\---



\## 3.6 完走ボーナス



| 行動       |    スコア |

| -------- | -----: |

| カイロを完走   | +1,000 |

| 残りHP1につき |   +200 |

| HP満タンで完走 | 追加+300 |



例：



```text

残りHP 3/3



完走　　　+1,000

HP　　　　+600

無傷完走　+300



合計　　　+1,900

```



HPを残す価値をスコアへ接続する。これによりREST、水筒、ゴーグル、RISK回避が記録狙いにも意味を持つ。

\# 4. 1投のスコア表示



1回のロールでは、発生した場所に合わせて順番に増やす。



```text

サイコロ停止

↓

3ROLL SLOTボーナス

↓

猫が1マス進むたび、初訪問なら+10

↓

停止マスボーナス

↓

SCORE表示が最終値へ到達

```



例：



```text

スロット：PAIR　　　+150

4マス移動　　　　　+40

ITEM取得　　　　　 +120



今回の合計　　　　 +310

```



「今回の合計」は常設しない。複数加点が重なった場合だけ、HUD付近に短く表示する。



\---



\# 5. HUD表示



通常旅行のHUDは次を基本とする。



```text

SCORE 001840　🪙12　♥♥♡　18/58　MAP

```



\### SCORE



\* HUD内で最も大きく表示

\* 6桁程度

\* 加点時は数字が滑らかにカウントアップ

\* 大きな得点ほど少しだけ強い音と光

\* カウントアップ中でもゲーム進行は止めない



\### 加点理由



スコアの近くに1行だけ表示する。



```text

PAIR +150

ITEM +120

ボス勝利 +1,000

```



小さい説明文を複数並べない。



\---



\# 6. スコア演出



\## 小得点：+10〜+50



\* 0.10〜0.18秒

\* 軽い数字送り

\* 小さなクリック音

\* 発光なし、または非常に弱い



\## 中得点：+100〜+400



\* 0.20〜0.30秒

\* 加点理由を表示

\* SCOREが一度軽く膨らむ

\* 短い上昇音



\## 大得点：+500以上



\* 0.30〜0.45秒

\* 金色または青緑の短い光

\* 数字が少し跳ねる

\* 全画面演出や確認ボタンは出さない



TRIPLE、黄金スカラベ、ボス勝利でも旅を長く止めない。



\---



\# 7. BEST SCORE



\## 保存単位



v0.1では、次の単位でBESTを保存する。



```text

ステージID × ゲームモード

```



例：



```text

cairo\_normal

cairo\_time\_attack

```



通常旅行とタイムアタックの記録は完全に分離する。



使用キャラクターはBEST記録のメタデータとして保存する。



```yaml

score: 6840

character: explorer\_cat

boss\_result: win

scarab: true

```



将来キャラクター別BESTを追加できるようにするが、v0.1では一覧を複雑にしない。



\## 更新タイミング



BESTは周回終了時だけ更新する。



\* 周回途中では保存しない

\* リタイアでは更新しない

\* アプリ中断から復帰して完走した場合は更新可能

\* 同点なら先に記録したものを維持

\---



\# 9. スコアを与えない行動



v0.1では、次には直接スコアを付けない。



\* サイコロを振っただけ

\* ピンポイントを使用しただけ

\* コインを使った

\* アイテム画面を開いた

\* MAPを見た

\* ポーズした

\* 同じマスを再訪した

\* イベント選択を開いただけ

\* スキルゲージがREADYになっただけ



入力回数や待ち時間を得点源にしない。



ピンポイントは、より良いマスや役を狙いやすくすることで、間接的にスコアへ貢献する。



\---



\# 10. 不正加点・二重加点防止



スコア処理は必ずイベントID付きで行う。



```text

score\_event:

&#x20; type: item\_land

&#x20; node\_id: main\_17

&#x20; lap: 1

```



同じ`node\_id + lap + type`が処理済みなら再加点しない。



セーブ対象：



\* 現在スコア

\* 分類別スコア

\* その周で訪問済みのマス

\* 加点済みイベント

\* ボス完走・勝利加点済みフラグ

\* 完走ボーナス加点済みフラグ



pause/resumeやアプリ中断で、同じITEMやボス勝利が二重加点されないようにする。



\---



\# 11. v0.1では入れないもの



\* スコア倍率

\* コンボゲージ

\* スコア減点

\* 残り時間ボーナス

\* コイン残量のスコア変換

\* オンラインランキング

\* 日替わりボーナス

\* キャラクターごとの倍率

\* ランダムな得点幅

\* 広告によるスコア増加



まずは\*\*何をすれば何点増えるかが透明な加算方式\*\*でテストする。



\---



\# 12. プレイテスト基準



カイロを5〜10周して確認する。



\* ほぼ毎投、何らかのスコア変化がある

\* 高い出目だけが常に最善にならない

\* ITEMやSTRAIGHTを狙う理由が生まれる

\* RISK回避の準備がスコアにもつながる

\* 円環へ寄るか本線を進むか迷う

\* MIXでも完全な失敗に感じない

\* ボス敗北後も、もう一周する気持ちが残る

\* BESTまでの差を見て、次の改善点を想像できる

\* 加点演出が一投のテンポを止めない

\* 通常旅行で時間のプレッシャーを感じない



\---



\## v0.1の核



> \*\*進むたびに少し増え、うまい判断で大きく増える。\*\*

> \*\*スコアは減らず、使う資源とは分離する。\*\*

> \*\*通常旅行は数字を大きくする遊び、タイムアタックは時間を小さくする別の遊び。\*\*



次はこの配点を既存実装へ照合し、現在入っているMIX・PAIR・STRAIGHT・TRIPLE、マス効果、周回結果の値をこの表へ統一するのが自然だね。
