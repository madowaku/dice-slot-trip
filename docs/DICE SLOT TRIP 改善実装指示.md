# DICE SLOT TRIP 改善実装指示
## 新90マスマップ + HP3固定 / LIFE3 + EVENT再配置 + スキル説明改善

添付済みの「DICE SLOT TRIP 現行仕様・相談用コンテキスト 2026-08-11」と、現在チェックアウトされているGodotプロジェクトの実装・テストを正として作業してください。

今回は新機能を大量に追加する改修ではありません。

家族スマホでの長時間プレイテストから得られたフィードバックを反映し、

1. 58マスでは短いため、通常マップを新しい90マス構成へ戻す
2. HPとゲーム全体の残機を分離する
3. 最大HP成長を廃止し、HPは常に3固定にする
4. ボス勝利後のハートルーレットを回復専用にする
5. EVENTを序盤から後ろへ移し、コインを使える状態になってから遭遇しやすくする
6. 探検猫スキルを説明なしでも理解できるUIへ改善する

ことが目的です。

既存のゲームループ、セーブ、ボス、スロット判定、サイコロ操作などを不用意に壊さないでください。

# 4. 近道をRISK / REST交互型へ統一

近道は引き続き無料です。

コイン支払い式には変更しません。

代償は「危険なマスを通ること」です。

## 近道1

基本イメージ：

```text
RISK → REST → RISK → REST
```

通常ルートより約4マス短縮する構造を目安にしてください。

## 近道2

基本イメージ：

```text
RISK → REST → RISK → REST → RISK
```

通常ルートより約6マス短縮する構造を目安にしてください。

重要：

「近道 = RISKだらけ」ではなく、

危険
↓
回復
↓
危険
↓
回復

という見た目だけでもルートの性格が理解できるようにします。

現在HPによって近道へ行くかどうかの判断が変わることを狙います。

# 6. HPを最大3固定へ変更

現行：

- 初期HP 3
- 初期最大HP 3

```text
HP_MAX = 3

```

新仕様では常に3として扱ってください。

HUDも、


# 7. HPとは別にLIFEストックを追加

新しいゲーム全体リソースとしてLIFEを追加します。

```text
初期LIFE = 3
LIFE最大 = 3
```

ここでのLIFEは「復活可能回数」です。

HUDには猫アイコン等のゲーム内画像を使用して、

```text
×3
```

のように小さく分かりやすく表示してください。

絵文字フォントには依存しないでください。

中央マップを圧迫しない位置に置いてください。

# 8. HP0時の処理

RISK等でHPが0になった場合：

## LIFEが1以上ある

```text
LIFE -= 1
HP = 3
```

としてその場で復活します。

GAME OVERにはしません。

短い復活演出を入れて構いませんが、長い説明モーダルは不要です。

例：

```text
LIFE -1
♥♥♥ FULL
```

程度で十分です。

## LIFEが0

この状態でさらにHPが0になった場合のみGAME OVERです。

つまり開始時のLIFE3は、

「HP0から3回まで復活できるストック」

として扱ってください。

---

# 9. コイン5枚による緊急復帰を廃止

現行の、

- コイン5枚
- 1旅1回
- HP1で緊急復帰

という処理は廃止してください。

理由：

今回LIFEを追加するため、

```text
HP
LIFE
コイン緊急復帰
```

の3層にすると生存ルールが複雑になります。

今後は、

```text
HP = その場の体力
LIFE = 復活ストック
COIN = EVENTや各種効果に使う通貨
```

と役割を明確に分離します。

関連するUI、説明、保存フラグ、テストも整理してください。

